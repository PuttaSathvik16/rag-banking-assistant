# Retail Banking Product & Policy Advisor — RAG Banking Assistant

A retrieval-augmented assistant that answers retail-banking product, fee, and eligibility
questions, grounded strictly in a synthetic disclosure corpus with clause-level citations and
abstention when the corpus doesn't support a confident answer.

Business case: `docs/business-case.md` · Acceptance criteria & traceability: `specs/acceptance_criteria.md`

## Stack
Python 3.11+ · LangChain · Google Gemini (generation + judge) · Chroma (vector store) ·
`rank_bm25` (lexical) · Sentence-Transformers (embeddings + CrossEncoder reranker) · RAGAS (eval).
No Docker, no external database service, no Claude — Gemini is the only approved LLM provider.

## Quick start

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env              # then add your GOOGLE_API_KEY

python cli.py setup               # generates the 33-doc corpus + builds the vector index
python cli.py ask "What is the minimum balance for Premium Savings?"
python cli.py eval                # runs RAGAS over the golden set -> eval/reports/
python cli.py compare-models      # two-model comparison -> eval/reports/model_comparison.md
```

Everything runs from `pip install` + these commands — no Docker, no external services.

## Architecture

```
question
  -> query transformation (Gemini rewrite/decomposition, AC-07)
  -> hybrid retrieval: BM25 + Chroma vector search, fused via RRF (AC-03)
  -> cross-encoder reranking -> top-K (AC-04)
  -> grounded generation: Gemini, Pydantic-validated JSON, clause citations,
     abstention below confidence threshold (AC-02, AC-05, AC-06)
```

| Layer | Module |
|---|---|
| Corpus generation | `scripts/generate_corpus.py` |
| Ingestion & chunking | `src/ingestion.py` |
| Hybrid retrieval + RRF | `src/retrieval.py` |
| Reranking | `src/reranker.py` |
| Query transformation | `src/query_transform.py` |
| Generation & grounding | `src/generation.py` |
| Structured output schema | `src/schemas.py` |
| Orchestration | `src/pipeline.py` |
| Eval harness (RAGAS + failure taxonomy) | `eval/run_eval.py` |
| Model comparison | `eval/model_comparison.py` |

## Configuration
All retrieval/chunking/generation parameters live in `config.yaml` (NFR-04) — nothing is
hardcoded in `src/`. Model IDs default to `gemini-2.5-flash`; verify current model availability in
Google AI Studio before your run, since Google periodically retires older model strings.

## Evaluation
`eval/golden_set.json` — 23 questions covering direct lookups, multi-part queries (AC-07), and
deliberate abstention cases (AC-05: a rate-by-tier question, a definitive-approval question, and
an out-of-corpus question). `eval/run_eval.py` computes RAGAS context precision/recall,
faithfulness, and answer relevancy, and classifies any misses into a retrieval / grounding /
synthesis failure taxonomy. Reports land in `eval/reports/` (git-tracked — commit them after your
run; uncommitted results score zero per the Evidence-in-Repo Rule).

## Guardrails
- Every non-abstained answer carries ≥1 clause-level citation.
- The assistant never issues a definitive eligibility/approval decision — it surfaces the
  applicable policy language and lets a human make the determination.
- Retries with exponential backoff on Gemini calls; any parse/validation failure degrades to a
  safe abstention response rather than crashing (NFR-05).

## Data
All 33 corpus documents are synthetic, generated by `scripts/generate_corpus.py`. No real
customer, account, card, or Virtusa-confidential data is used anywhere in this repository.

## Tests

```bash
pytest tests/ -v
```
`tests/test_retrieval.py` covers AC-03/AC-04. `tests/test_generation.py` covers AC-05/AC-06.
